Monitoring images render the real app against isolated synthetic fixtures. Identity, process IDs and observations are demonstration data rather than production telemetry. Other existing public-portfolio captures retain their original provenance.

在 `frontend/` 執行：

```sh
npm run docs:capture   # 全部 Profile 與監控圖片
npm run docs:profile   # 只更新 Profile
npm run docs:monitor   # 只更新監控
```

`playwright.docs.config.ts` 啟動測試 API（4181）與 production preview（4173），`tests/e2e/*-docs.capture.ts` 使用既有 HTTP／Engine.IO／owner fixtures、Mint 主題、暫停裝飾動畫與已載入字型擷取。監控僅更新手機圖可加上 `PORTFOLIO_DOCS_PHONE_ONLY=1`。結果直接覆寫上述 PNG，不連線設定中的後端，也不保存 cookie 或瀏覽器網址列。修改 UI 後需檢視產圖再提交。

The dedicated documentation configuration starts the isolated fixture API and production preview, then captures settled Mint layouts with shared fixtures. Inspect generated PNGs before committing; runtime assets do not depend on documentation images.

更新圖片時保留既有檔名與功能對應，確認文字、卡片、包邊及控制沒有被意外截斷。對話框／抽屜應在進場完成後擷取，等待字型、內容與圖片載入，並讓裁切保留功能所需的上下文。PNG 不包含瀏覽器網址列、桌面或操作紀錄。展示文字與日期屬於 API 內容，不作為固定文案規格。

When refreshing images, preserve filenames and feature mappings. Retain readable text, card edges and necessary controls. Capture dialogs and drawers after entrance completes and after fonts, content and images load. PNGs contain the interface only, without browser chrome, desktop surfaces or operational records. Displayed text and dates are API content rather than fixed copy requirements.
